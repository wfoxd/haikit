Each user's own OAuth account. `createMcpAuth` takes `store`, `secret` and `redirectUri`, and then `mcpAuth.oauth({ issuer?, scopes?, client? })` makes a server's calls with the tokens each user connected: through `mcpAuth.handler()`'s routes, a connect route that sends the browser to the server's authorization server with PKCE and the resource indicator, and a callback that checks `iss`, stores the tokens and shows a done page that tells the window that opened it. `requestUser` says who is signed in for the routes, `onConnected` hears each connect, with the conversation the link was for if it's the user's, and `basePath` (`"/mcp"`) and `clientName` are optional. With no `client`, one is registered for the app, by its client metadata document where the authorization server takes one, else by dynamic registration. A 401 refreshes the user's credential, once for all the requests that got one, and once across app processes sharing the store; a refusal deletes it and rejects with `reconnect`, and an outage keeps it and rejects with `connection`. Credentials are kept in a `CredentialStore`, `memoryCredentialStore()`, or `pgCredentialStore(db)` from the new `@haikit/mcp/postgres` subpath, with `migrate` and `schema`, sealed with AES-256-GCM and bound to their row; `secret` can be a list, to rotate. `mcpAuth.connections(userId)` lists what a user connected (`McpAccount`), and `mcpAuth.disconnect(userId, server?)` revokes, deletes and closes. `mcpAuth.sdk(make)` takes one of the SDK's own providers for each user, and `OAuthClientProvider` is re-exported. An `auth` error from an `oauth()` server has `err.auth.connect` (`McpAuthNeed.connect`), the app's connect link for it, asking for the scope a 403 named. `McpErrorReason` is unchanged; `McpServerAuth.kind` has two more members, `"oauth"` and `"sdk"`, so a `switch` over it that must be exhaustive needs cases for them.
